# 中文歌词创作

## 用途

按指定歌手、歌曲或曲风写原创中文歌词，输出可直接投喂音乐生成模型的结构化文本。核心动作是把"像某首歌"拆成可复现的风格特征，再按特征新写，而不是复述原曲句子。

## 触发场景

- 点名某歌手或某首歌，要求仿写、"再来一首"
- 指定曲风（民谣、R\&B、古风、说唱、叙事民谣）要求原创歌词
- 已有歌词要求改风格、改韵脚、改段落结构

## 工作流

### 第 1 步：提取风格指纹

拿到参考对象后，先判断属于哪种原型（查 `references/style-fingerprints.md`），确认五项特征：

1. **叙述视角**——第一人称回忆 / 第二人称对话 / 第三人称寓言
2. **句式长度**——短句碎片化（民谣叙事）还是长句整块（华语大流行副歌）
3. **意象密度**——实物白描（冰棍、粮票）还是抽象隐喻（捕食、驯服）
4. **押韵习惯**——句尾全押 / 隔句押 / 只押副歌
5. **情绪曲线**——平铺到底 / 副歌一次爆发 / 桥段反转

参考对象不在档案里时，按这五项现场拆解，把结论说出来再动笔。**只借风格特征，不借歌词文本。**

### 第 2 步：定结构与时长

| 目标时长     | 段落配置                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 3–3.5 分钟 | Verse1 · Pre-Chorus · Chorus · Verse2 · Chorus · Bridge · Final Chorus · Outro |
| 约 4 分钟   | Verse1 · Chorus · Verse2 · Chorus · Verse3 · Bridge · Final Chorus · Outro     |
| 4.5 分钟以上 | 上述基础上加器乐间奏位、末段副歌转调                                                             |

段落用方括号标注，便于音乐模型解析：`[Verse 1]`、`[Pre-Chorus]`、`[Chorus]`、`[Bridge]`、`[Final Chorus]`、`[Outro]`。

### 第 3 步：定韵部、先排韵脚（不要写完再补）

押韵和读音不是两个指标，它们共用一个位置：**韵脚**。韵脚字是耳朵唯一期待的落点，也是念错最刺耳的位置。所以它必须在写句之前定好。

1. **一段一韵**。按情绪选韵部（中华新韵十四韵）：`寒`(an/ian/uan/üan) 适合叙事与乡愁，`唐`(ang/iang/uang) 开阔、适合副歌与回忆，`尤`(ou/iu) 低沉收束，`开`(ai/uai) 松弛，`齐`(i/ü/er) 细密偏冷。
2. **对句押韵**。偶数行是押韵行（第 2、4、6…行），奇数行自由。这是华语歌词的默认规则，句句押是加分项而非必需。**不要要求每行都押**——那正是把句子写僵的主因。
3. **韵脚字三条硬约束**：GB2312 一级常用字、单音字、不用句末语气词（啊/呢/吧/啦）。读错的韵脚会让整段散韵，语气词会让韵悬空。
4. **先把韵脚排成竖列，再填前半句**：

   ```
   面 / 年 / 线 / 天      ← 全是 an 韵、全是一级字、全是单音
   我捏着两毛钱 守在冰棍箱的后面
   车座上驮着黄昏 驮着我整个童年
   声调拖得很长 像风筝的线
   那些我以为 散不掉的 都留在昨天
   ```

   韵脚定死之后再去写每行前半句，句子自然会往那个落点上长。反过来做（先写句子再找韵）必然要么出韵，要么硬凑。
5. **钩子行反复出现必须同字**。副歌重复三次，收尾字不能"意思一样、换个近义词"。

### 第 4 步：写初稿

硬规则：

- **具体压过抽象**。写"两毛钱的冰棍"，不写"童年的美好"；写"未读消息挂在那一格"，不写"我很想你"。
- **副歌只留一个钩子**，能被记住、能单独成句。整首歌一个记忆点，不要每段都用力。
- **情绪靠事实推**。删掉"难过、心痛、孤独"这类词，用动作和场景替代。
- **末句反转或留白**。最后一行要么把前面意思翻一面，要么收在一个动作上（"就当 他们看见了"）。
- **单行 7–14 字**。超过 16 字的行在音乐模型里容易被吞字，YuE2 尤其明显。
- **押韵按第 3 步的韵脚列执行**。奇数行可以完全不押，偶数行不许出韵——一句出韵，整段散架。

### 第 5 步：自检（机器两遍）

先跑机器检查，再做人工判断：

```bash
python3 scripts/check_lyrics.py 歌词文件.md      # 或 --text "单行歌词"
```

脚本先审押韵、再审发音，两栏一起看：

```
[押韵] 对句押韵审计
  Chorus  押韵行 3/3 同「唐」 · 成立
    押韵行韵脚：样(唐) 方(唐) 望(唐)
```

判读：`成立` 才算过；`有出韵` / `不成立` 先改韵脚，别急着改发音。`通押` 是十三辙层面的宽判，可接受但要自己听一遍。

脚本拦截六类发音风险。核心是三类、三层机制：

| 机制 | 例 | 成因 | 解法 |
|---|---|---|---|
| 字级 A：低频字·同音无兜底 | 攥(zuàn) → zhuàn/zuān | 非一级常用字，且该音下同音常用字≤2 个，只能落到别音 | 必换 |
| 字级 B：低频字·有同音兜底 | 筝(zhēng) → 争/征/睁 | 同音常用字≥3 个，读错也落在同音字上，听感不变 | 可留，实听一次再定 |
| 词级：非常用搭配被先验覆盖 | 低吠 → 低垂/低声 | 单字都常见，但组合不在常用词表，模型按语言先验补成高频词 | 换成词表内的固定搭配（犬吠、低吼） |
| 读音级 A：词表外 + 少数派读音 | 知了(liǎo) → 知le | 词不在常用词表，没有读音样本，只能逐字取音 | 必换（`polyphone-words.tsv` 已覆盖 77 个高发词） |
| 读音级 B：词表内 + 少数派读音 | 长大(zhǎng)、还给(huán) | 词高频出现，模型有足够样本，多半学对 | 保留，实听后再定 |

分档依据：**字级看同音密度**（数据来自 `char-homophone.tsv`），**读音级看词是否在 45k 常用词表**。两个 B 档都不是安全，只是可留：獠(liáo) 同音字 11 个仍被读成 luǒ，所以 B 档允许先留着跑一次，听过再决定。

**取舍原则：发音安全是约束，不是目标。优先级不能反。**

1. **歌词质量优先。** 意象、语感、韵脚是第一位的；读音风险是第二位，且只能在不牺牲质量的前提下解决。
2. **只换同强度的词。** 换完必须不比原词弱。反例：知了→蝉儿（儿化让语气软了）、弹珠→小珠子（具体物件泛化）、攥着→捏着（力道掉了）。正例：知了→蝉（更利落，chán 还接上了 an 韵）、弹珠→玻璃球（同样是具体物件）。
3. **当安全要求逼你写平庸词时，说明方向错了。** 这时候要换意象，不是降质感。一首歌读起来不像歌，比一个字念错严重得多。
4. **只有标「必换」的才强制改。** 标「可留听」的保留原文，实听一遍再决定——多跑一次生成，好过把词写平庸。
5. **词频比读音占比更重要。** 模型是按词的统计规律学读音的。词高频（长大 1498、还给 269）就有样本；词低频（知了 0、弹珠 3）只能逐字取音。

**与押韵冲突时，优先级固定为：韵脚 > 读音 > 用词新奇度。** 要换韵脚字就整段换韵部（或换这一段的落点句），不要只替换其中一个韵脚字——单行出韵比一个字念错更刺耳；而 YuE2 没有局部修补，改一处就要整首重跑，这个成本比一开始把韵脚定对高一个量级。

三类都无法通过提示词或重跑修正，因为模型不看读音，只看字面与搭配概率。判定依据：末字不常独立成词 + 组合不在 45k 常用词表 + 首字有极高频搭配，三条同时成立才判为漂移，否则视为正常跨词组合。

**一条可直接执行的铁律**：多音字只取它最高频的那个读音。原意需要另一个读音时，整词换掉，不要赌。

| 字 | 安全（多数派读音） | 危险（少数派读音） |
|---|---|---|
| 了 | 走了、亮了、忘了（le） | 知了、了解、未了、受不了（liǎo） |
| 长 | 很长、长短（cháng） | 长大、成长（zhǎng） |
| 还 | 还有、还是（hái） | 还给、归还（huán） |
| 重 | 很重、重量（zhòng） | 重逢、重复（chóng） |
| 数 | 数字、无数（shù） | 数不清、数着（shǔ） |
| 弹 | 子弹（dàn） | 弹琴、弹吉他（tán） |

人工清单：

- [ ] 有无整句照搬参考歌曲？有则重写。
- [ ] 副歌钩子是否唯一、是否可记？
- [ ] 是否存在"形容词+抽象名词"的空转句？删。
- [ ] 每行是否都在 14 字以内？超长拆行。
- [ ] 桥段是否提供新信息，而不是复述副歌？
- [ ] 末段是否收得住（降调、减配、留白）？
- [ ] 意象是否统一？一首歌里不要既写菜刀又写宇宙。
- [ ] 多音字逐字确认读音：凡是你自己会犹豫该念哪个音的，一律换字或换词。

### 第 6 步：输出

固定格式：标题行 + 正文 + 曲风提示串。

```
**《歌名》**——一句风格定位，约 X 分钟。

[Verse 1]
...

---

曲风建议（可直接投喂 YuE2）：语种、曲风、人声性别与音区、编曲乐器、BPM、情绪。
```

曲风串必须显式写人声性别与音区（如"男声中低音，气声"）。文字条件在 YuE2 里是软约束，若反复出现性别不符，正确解法是改写乐谱音域，不是在提示词里加倍强调。

## 参考资源

- `scripts/check_lyrics.py`——双栏检查器。先做**对句押韵审计**（韵部、出韵行、韵脚字自身风险），再报发音风险（低频字、少数派读音词、搭配漂移、多音字、叠词、数字字母、超长行）。
- `references/char-tables/polyphone-words.tsv`——77 个"必须读少数派读音"的高发词，每条带应读、易错读音与改法。写词时不要使用表中出现的词。
- `references/char-tables/pinyin-gb2312.tsv`——6,763 个 GB2312 汉字的带调拼音（含多音），押韵审计的数据源。
- `references/char-tables/char-homophone.tsv`——3,008 个非一级字的同音兜底强度（拼音 + 该音下一级常用字数），用于把低频字分为"必换"与"可留听"两档。
- `references/char-tables/level1-3755.txt`——GB2312 一级常用字表，判定低频字的基准。
- `references/char-tables/collocations-45k.txt`——45,810 个常用双字词（jieba 词频 ≥20），判定搭配是否常见。
- `references/char-tables/prefix-top.tsv`——按首字汇总的高频搭配，用于预测漂移目标。
- `references/char-tables/char-freq.tsv`——单字独立成词的词频，用于区分"词+词"与"复合词"。
- `references/char-tables/polyphone-gb2312.tsv`——GB2312 范围内多音字全表，供脚本扩展筛选。
- `references/style-fingerprints.md`——四类已沉淀风格档案（怀旧民谣叙事 / 都市夜 R\&B / 寓言式华语流行 / 古风叙事），含句式、押韵、意象库、禁忌。写新风格前先查表。
- `references/worked-examples.md`——已交付样章的技法拆解，作为质量标准锚点。
