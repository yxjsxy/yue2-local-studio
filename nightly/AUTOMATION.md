# 午夜八首：每天执行的最小工作流

本流程在用户启用定时任务后，于每天北京时间 00:00 写 8 首原创中文歌词、生成完整歌曲并发布到本机合集。执行前核对排程的实时状态；此前的暂停记录只是历史状态。当前排程启用且收到本任务唤醒时，执行当天批次；当前暂停时，不因旧提示自行新增批次。本文件不构成恢复排程的授权，不要自行启用排程，也不要改动其他定时任务。

项目绝对目录：`<项目目录>`。
Python：项目 `.venv/bin/python`。服务：`http://127.0.0.1:8766/library`。
歌词 skill：`skills/cn-lyric-writer/SKILL.md`。

## WorkBuddy 每晚写词与审稿

1. 用 `datetime.now(ZoneInfo('Asia/Shanghai'))` 获取日期；检查 `nightly-data/YYYY-MM-DD/manifest.json`。已有清单则不再写词，直接验证并恢复队列。已完成的同日批次退出，不重复运行。查看前一批 state.json，若失败只报告真实错误；不要无限重试。
2. 新批次阅读指定 skill 及其风格指纹。仅从近 7 天 manifest 提取标题和一句主题以避重复，不把全部历史歌词送进上下文。不浏览网络、不读模型源码、不下载权重。一次集中创作 8 首，固定为 folk/jazz/rap/pop × male/female，各组合恰好一首。8 首必须不同歌词、主题和标题，不能只改男女声提示词。
3. 遵循 skill 的韵脚优先、原创、具体场景、单一副歌钩子、桥段推进和动作留白。先排每段偶数行韵脚，随后写正文。每行 7–14 个汉字；一首 40–56 行，完整段落，重复副歌需逐字展开。禁止复制既有歌手歌词。保留简短 fingerprint 和 editorial_review。审稿不能只是声称完成，要实际检查意象、钩子、语意、少数派读音。不要为押韵写不自然的句子。
4. 曲风串使用英文描述、Mandarin Chinese，显式写唯一主唱的性别和音区、编配、BPM、演唱方式与情绪。民谣 80–100 BPM；爵士 95–115 BPM；说唱 88–105 BPM；明亮流行 110–128 BPM。folk/jazz/pop 使用 full，rap 使用 off。目标 210 秒，实际时长由模型决定，不能通过截短歌词或拼接凑数。声音性别只是软约束，不能标成已验证。
5. 保存下面结构的 UTF-8 JSON 到 `nightly-data/YYYY-MM-DD/manifest.json`。新建目录，不能覆盖已有批次。使用当日日期和槽位确定稳定随机种子。

```json
{
  "batch": "YYYY-MM-DD",
  "lyric_author": "WorkBuddy（模型未知）",
  "skill": "skills/cn-lyric-writer/SKILL.md",
  "songs": [
    {
      "slot": "folk-male", "genre": "folk", "voice": "male",
      "title": "原创歌名", "description": "一句具体主题",
      "fingerprint": "视角、句式、意象、押韵、情绪曲线",
      "editorial_review": "实际审稿结论和修改说明",
      "lyrics": "[Verse 1]\n完整歌词…",
      "style": "Mandarin Chinese, gentle acoustic folk, solo male baritone, ...",
      "mode": "full", "target_seconds": 210, "seed": 123456
    }
  ]
}
```

6. 在项目目录执行：

```sh
.venv/bin/python nightly/pipeline.py validate --manifest nightly-data/YYYY-MM-DD/manifest.json
```

检查器调用指定 skill 的脚本，再补充严格韵脚、行长和组合覆盖检查。若失败，只读取 validation.json 中失败条目和对应 audit 文件，集中修改这些歌曲；修好后再跑一次。最多 3 轮，不能通过修改检查器、空审稿或降预算绕过失败。实测音频质量与静态歌词检查须明确区分。

7. 验证通过后执行：

```sh
.venv/bin/python nightly/pipeline.py start --manifest nightly-data/YYYY-MM-DD/manifest.json
```

启动几秒后只检查一次 state.json/worker.log，确认 worker 已开始或同批次已运行，随后结束代理运行。不要为了音频推理长时间占用 WorkBuddy 的模型，不每隔几十秒让代理读日志。后台 Python 会串行提交、等待、重试、更新合集与 REPORT.md。正常运行保持安静，失败才提示用户。下一次排程可读前一批完成摘要。

`start` 现在后台启动的是 `supervise` 守护：它按轮调用 `run`，一轮异常退出不会让整批停在半路；凭 client_key 幂等，重复运行只补跑未完成的歌曲，不重跑已完成的成品。前一批未完成且 worker 已退出时，直接重新 `start` 同一清单即可续跑，不改动清单。

## 本地队列的职责

- 同时一个 worker、一个模型任务；每首最多 2 次尝试，第二次换固定种子。相同日期/组合/尝试具有幂等键，重复启动不会重复生成已完成的音频。
- 单首异常不得终止整批：提交、等待、汇总中的网络或任务异常只记录到该歌曲，并继续下一首；只有 STOP 文件、磁盘不足和整批/单曲超时才停止后续提交。
- 汇总不是关键路径：`/api/library` 短时不可用时，结果以本机 `studio-data/*/job.json` 的任务记录为准写入 state.json 与 REPORT.md，并在报告中注明降级原因，不再让一次连接失败毁掉整批。
- 服务自愈：每首提交前与完成后检测本地服务；不可达时用既有 `studio_ctl.py start` 幂等拉起并等待恢复，不重启正在生成歌曲的服务。HTTP 层连接错误按退避序列重试约 4 分钟；HTTP 4xx/5xx 仍原样抛出、不吞掉 409/410 语义。
- 默认完整歌曲预算 360 秒、曲谱 8192 tokens、单曲 90 分钟保护、整批 14 小时保护。不会循环拼接、补静音或变速凑时长。
- 可用磁盘低于 12 GiB 停止；只在工作期间防止空闲睡眠。电脑需要开机，应用需要在排程时运行；合盖、关机或强制睡眠不能保证任务执行。
- 成功、失败、截断、中断均如实保存；失败尝试不算新增成品。不自动无限追加或替换成功歌曲。
- `http://127.0.0.1:8766/library` 是用户长期使用的个人播放器。之后每一批生成的成品必须自动加入这个同一列表服务；保留原来的歌曲、歌词和音乐指令，不另建孤立播放器、不覆盖旧批次、不只显示当天。每首生成完成即入库，支持单曲循环和列表随机循环。
- 所有历史成品留在项目内，合集可按日期、曲风、目标声线和歌词检索。不要设置 40 首上限。除非用户另行明确要求删除，不自动清理旧歌；此前删除不足一分钟和已取消历史产物仅针对当时指定的历史记录。磁盘不足时停止新增并报告，不擅自删除收藏。
- 单批停止：创建该批目录的 `STOP` 文件，队列会取消当前任务并停止后续提交；恢复时经用户意图确认移除 STOP，再运行 start。
- 服务启动命令：`.venv/bin/python studio_ctl.py start`。不要重启仍在生成歌曲的服务。

写词使用 WorkBuddy 当前选择的模型。已知模型名时填入 lyric_author，无法确认时填“WorkBuddy（模型未知）”。YuE2 在本机生成音频。

## 音频保存格式

个人播放器使用 320 kbps MP3。YuE2 原生生成 FLAC 后，由服务调用本地 FFmpeg 转码；完整解码、时长、采样率、声道和哈希校验通过后，才删除原 FLAC。转码失败必须保留原件并报告，不能重新跑模型冒充重试转码。所有后续成品与历史成品共用同一 MP3 播放列表和下载入口。转码不调用写词模型。

## 个人播放器的真实进度

工作台和合集必须显示当前歌曲的具体阶段：模型加载、曲谱生成/完成（直接模式明确跳过）、演唱与编配序列、音频合成的实际 n/N 步、解码的实际 n/N 块、原音频校验、MP3 转码、MP3 完整解码校验、清理原 FLAC、入库完成。进度来源仅为模型原生日志、真实回调和 FFmpeg 的已处理音频时间。没有真实总量时只显示阶段和已完成量；不得把 token 预算或目标歌曲时长充当总进度，不编造整体百分比或剩余时间。MP3 转码进度表示本阶段已处理秒数/原音频总秒数；100% 转码后仍需校验，校验通过才删除 FLAC。后台程序记录进度，前端本地请求刷新，不使用写词模型轮询。失败显示具体失败阶段并保留原件。不得为部署进度界面中断正在生成的歌曲；静态界面可立即更新，后端等待自然空闲再部署。

下载命名统一为 `小Rei-歌名.mp3`，工作台与合集使用同一歌曲标题，不用任务 ID 命名。尚未迁移的原音频保留真实扩展名，不能把 FLAC 内容仅改名为 MP3。

下载文件名必须同时通过带中文歌名的下载 URL 和 HTTP `Content-Disposition` 的 UTF-8 `filename*` 指定；不能仅依赖前端 `download` 属性。媒体播放器自带下载入口也应返回正确文件名。修改后验证实际下载文件名。

个人播放器持续播放：复用同一个音频元素，刷新歌曲目录不得重置音频。切歌时忽略过期播放请求的错误；区分浏览器播放许可、加载中断和解码失败，不能统一提示点击播放。短暂加载故障至多自动重试一次，手动暂停后不得自动恢复；实际播放成功后清除错误。播放器修改须验证歌曲自然结束后的列表/随机续播，以及单曲循环，不以点击下一首成功代替自动续播验证。

本地 HTTP 服务使用 `StudioHTTPServer` 的 64 个待接入连接队列，避免多个页面/音频同时重连时默认 5 个队列导致超时。目录刷新必须串行并设超时；无生成任务时不额外轮询全部任务状态，后台标签页降低刷新频率。服务变更后验证音频 Range 请求和目录查询同时发起仍可成功。

## 个人收藏与永久删除

用户可以在合集点击心标，将歌曲加入持久的“我喜欢的歌”歌单；歌单支持现有筛选、歌词、单曲循环和随机循环。收藏数据保存在本机 `studio-data/library-state.json`，不能因新批次、刷新或重启被覆盖。

只有用户在页面确认删除或明确指定歌曲时，才永久清理该歌曲的音频、曲谱、生成中间文件、同槽位的失败尝试，以及哈希相同的重复发布副本。正在生成的歌曲禁止删除。保留很小的删除记录，防止原批次恢复时重新生成或显示等待生成占位；不清理用户其他歌曲或共享模型。删除不构成全库自动清理的授权。队列收到已删除歌曲的 HTTP 410 时跳过它，已删槽位单独计数，不冒充当前可播放成品。
